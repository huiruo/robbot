## 当前结论

当前桌面端已经完成最小闭环：Renderer 页面点击“发送到 DSH”后，请求会经过 Electron Preload、Main Process、`@robbot/dsh-adapter`，最后启动 vendored `deepseek-harness`，通过 ACP JSON-RPC 调用 DeepSeek，并把 assistant 输出返回到前端。

## 总体链路

```text
apps/desktop/renderer
  App.tsx
  用户点击“发送到 DSH”
        ↓
apps/desktop/electron/preload
  window.robbot.harness.runPrompt(prompt)
        ↓
apps/desktop/electron/ipc
  ipcMain.handle('harness:run-prompt')
        ↓
apps/desktop/electron/main/harness
  HarnessService.runPrompt(prompt)
        ↓
packages/dsh-adapter
  DshLocalHarness.createSession()
  DshLocalHarness.run()
        ↓
packages/dsh-adapter/transport
  AcpTransport
  JSON-RPC over stdio
        ↓
packages/dsh-adapter/transport/process
  DshProcess
  spawn Node + tsx + DSH ACP demo entry
        ↓
vendor/deepseek-harness
  packages/examples/acp-demo/src/bin.ts
  examples/acp-agent/cordis.yml
        ↓
DeepSeek API
```

## 分层职责

| 层 | 位置 | 职责 |
|---|---|---|
| Renderer | `apps/desktop/renderer/src/App.tsx` | 负责页面交互、展示状态、展示运行结果和链路日志。 |
| Preload | `apps/desktop/electron/preload/index.ts` | 暴露安全 API：`window.robbot.harness.*`。Renderer 不直接访问 Node、DSH、`.env`。 |
| IPC | `apps/desktop/electron/ipc/index.ts` | 接收 Renderer 请求，转发给 Main 侧服务。 |
| Main Service | `apps/desktop/electron/main/harness/harness-service.ts` | 桌面端业务编排：检查 runtime、创建 session、发送 prompt、收集事件、返回结果。 |
| Core Contract | `packages/core` | 定义稳定接口：`LocalHarness`、`HarnessEvent`、`HarnessSession`、approval 类型等。 |
| DSH Adapter | `packages/dsh-adapter` | 把 Robbot 的核心接口适配到 DeepSeek Harness ACP 协议。 |
| DSH Runtime | `vendor/deepseek-harness` | DeepSeek Harness 源码，以 git submodule 形式 vendored 到 Robbot。 |

## Renderer → Preload

Renderer 调用：

```ts
await window.robbot.harness.runPrompt(prompt)
```

这个 API 来自 Preload：

```ts
contextBridge.exposeInMainWorld('robbot', {
  harness: {
    getStatus: () => ipcRenderer.invoke('harness:get-status'),
    runPrompt: (prompt: string) => ipcRenderer.invoke('harness:run-prompt', prompt),
    onLog: (listener) => { ... },
  },
})
```

设计约束：

- Renderer 不读取 `.env`。
- Renderer 不直接启动 DSH。
- Renderer 不直接接触 Node `child_process`。
- Renderer 只通过白名单 API 访问 Main。

## Preload → Main IPC

IPC handler：

```ts
ipcMain.handle('harness:run-prompt', (event, prompt: string) => {
  services.harness.setLogSink((entry) => {
    event.sender.send('harness:log', entry)
  })

  return services.harness.runPrompt(prompt)
})
```

这里做两件事：

1. 调用 `HarnessService.runPrompt(prompt)`。
2. 把 Main / Harness / DSH 的链路日志通过 `harness:log` 推回 Renderer。

## HarnessService 编排

`HarnessService.runPrompt()` 是桌面端当前最核心的入口。

执行顺序：

```text
1. trim prompt
2. 计算 workspacePath
3. harness.createSession({ workspacePath })
4. harness.run(session.id, { prompt })
5. 遍历 HarnessEvent
6. 收集 assistant.delta 到 text
7. 遇到 run.failed 抛错
8. run.completed 后返回 sessionId、text、events
```

当前 workspacePath：

```ts
path.resolve(process.cwd(), '../..')
```

在 `apps/desktop` dev 场景下会解析到 Robbot 仓库根目录：

```text
/robbot
```

## DSH Adapter → ACP

`DshLocalHarness` 对外实现 `LocalHarness`：

```ts
createSession(input) → AcpTransport.createSession(input)
run(sessionId, input) → AcpTransport.run(sessionId, input)
interrupt(sessionId) → AcpTransport.cancel(sessionId)
approve(sessionId, input) → AcpTransport.approve(sessionId, input)
```

`AcpTransport` 负责 ACP JSON-RPC：

| Robbot 行为 | ACP method |
|---|---|
| 初始化连接 | `initialize` |
| 创建 session | `session/new` |
| 发送 prompt | `session/prompt` |
| 取消运行 | `session/cancel` |
| 监听模型输出 | `session/update` notification |
| 处理权限请求 | `session/request_permission` |

当前 assistant 输出来自：

```text
DSH session/update
  update.sessionUpdate = agent_message_chunk
  update.content.type = text
        ↓
AcpTransport 转成
  { type: 'assistant.delta', text }
        ↓
HarnessService 拼接到 result.text
        ↓
Renderer 展示
```

## DSH 子进程启动

`DshProcess` 当前启动命令等价于：

```bash
node --import tsx packages/examples/acp-demo/src/bin.ts \
  --config examples/acp-agent/cordis.yml
```

工作目录是：

```text
vendor/deepseek-harness
```

也就是说实际入口是：

```text
vendor/deepseek-harness/packages/examples/acp-demo/src/bin.ts
```

配置文件是：

```text
vendor/deepseek-harness/examples/acp-agent/cordis.yml
```

环境变量：

| 变量 | 来源 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 进程环境或 Robbot 根目录 `.env` | DSH 调用 DeepSeek API 使用。不要在日志中打印。 |
| `DSH_PERMISSION_MODE` | 默认 `danger-full-access` | 当前调试阶段为了跑通文件/命令能力。产品化后应改成可控 approval。 |
| `TSX_TSCONFIG_PATH` | DSH 根目录 `tsconfig.json` | 保证 tsx 使用 DSH 自己的 tsconfig。 |

## 日志说明

当前日志分四类：

| source | 含义 |
|---|---|
| `renderer` | 页面动作，例如点击发送、刷新状态、Promise resolved/rejected。 |
| `main` | Electron Main 收到请求、查询 runtime 状态。 |
| `harness` | Robbot HarnessService 业务节点，例如创建 session、发送 prompt、完成 run。 |
| `dsh` | DSH/ACP 事件，例如 `run.started`、`assistant.delta`、`run.completed`。 |

终端额外有两类底层日志：

| prefix | 含义 |
|---|---|
| `[robbot:dsh-process]` | DSH 子进程启动、退出、Node 路径、cwd。 |
| `[robbot:acp]` | ACP JSON-RPC 请求/响应。 |

## 当前还不是最终产品态的点

当前实现是“最小可见闭环”，不是完整聊天产品。

下一步建议：

1. 改成真正流式 UI：`assistant.delta` 到达即追加到页面，而不是等 `runPrompt()` 全部结束后一次性展示。
2. session 复用：当前每次发送都会创建一个新 session，后续应保留当前会话上下文。
3. approval UI：把 `approval.required` 转成页面弹窗/确认按钮，而不是默认危险权限。
4. workspace 选择：让用户明确选择 DSH 操作哪个项目目录。
5. interrupt/cancel：运行中支持取消，对应 ACP `session/cancel`。
6. 日志级别开关：调试期开详细日志，正式版默认关闭或降级。
