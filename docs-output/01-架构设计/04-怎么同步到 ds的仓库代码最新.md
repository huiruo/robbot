# 怎么同步 vendor/deepseek-harness 到 DeepSeek 官方仓库最新代码

## 当前状态

Robbot 通过 git submodule 引入 DeepSeek Harness：

```text
vendor/deepseek-harness
```

`.gitmodules` 当前配置：

```ini
[submodule "vendor/deepseek-harness"]
    path = vendor/deepseek-harness
    url = https://github.com/deepseek-ai/deepseek-harness.git
    branch = master
```

当前 submodule 指向：

```text
99f6f02fecdb7dff40c3fbc9470f5907c29f74ca vendor/deepseek-harness (dsh-v0.1.0-rc.7)
```

这意味着：

- `vendor/deepseek-harness` 是一个独立 Git 仓库。
- Robbot 主仓库只记录它当前锁定在哪个 commit。
- 更新 DSH 后，Robbot 主仓库会出现一个 submodule 指针变更，需要一起提交。

## 推荐方式：使用项目脚本

仓库里已经有脚本：

```text
scripts/dsh-update.ts
```

推荐直接执行：

```bash
cd /robbot
pnpm dsh:update
```

这个脚本会自动做这些事：

```text
1. 检查 vendor/deepseek-harness 是否存在
2. 检查 submodule 内部是否有未提交改动
3. 从 .gitmodules 读取跟踪分支，当前是 master
4. git fetch origin
5. checkout origin/master
6. 在 DSH 内 pnpm install --frozen-lockfile
7. 在 DSH 内 pnpm run build
8. 回到 Robbot 跑 pnpm test:dsh
9. 回到 Robbot 跑 pnpm test
10. 输出升级报告
```

如果全部通过，最后按提示查看 diff：

```bash
git diff --submodule=log vendor/deepseek-harness
```

确认没问题后提交：

```bash
git add vendor/deepseek-harness pnpm-lock.yaml
git commit -m "chore: update deepseek-harness"
```

如果更新过程中 Robbot 自己的 package lock 没变化，可以不加 `pnpm-lock.yaml`；以 `git status` 为准。

## 手动同步方式

如果不用脚本，可以手动执行。

### 1. 进入 Robbot 主仓库

```bash
cd /robbot
```

### 2. 确认 submodule 当前状态

```bash
git submodule status vendor/deepseek-harness
```

查看 DSH 内部是否干净：

```bash
git -C vendor/deepseek-harness status --short
```

如果这里有输出，说明 DSH submodule 内部有未提交改动。不要直接覆盖，先判断这些改动是否要保留。

### 3. 拉取官方最新代码

```bash
git -C vendor/deepseek-harness fetch origin
```

### 4. 切到官方 master 最新 commit

```bash
git -C vendor/deepseek-harness checkout origin/master
```

说明：这里会让 submodule 处于 detached HEAD，这是 submodule 的正常用法。Robbot 主仓库记录具体 commit，而不是记录一个本地分支名。

### 5. 安装并构建 DSH

```bash
cd vendor/deepseek-harness
corepack pnpm install --frozen-lockfile
corepack pnpm run build
```

### 6. 回到 Robbot 跑 contract test

```bash
cd /robbot
pnpm test:dsh
```

`pnpm test:dsh` 必须通过，因为它验证 Robbot 和 DSH 的 ACP contract 是否仍兼容。

### 7. 跑 Robbot 全量测试

```bash
pnpm test
```

如果当前阶段全量测试包含较重的桌面构建，也至少要保证：

```bash
pnpm test:dsh
pnpm --filter @robbot/core build
pnpm --filter @robbot/dsh-adapter build
pnpm --filter @robbot/desktop build
```

### 8. 查看 submodule 变更

```bash
git diff --submodule=log vendor/deepseek-harness
```

你会看到类似：

```text
Submodule vendor/deepseek-harness oldsha..newsha:
  > commit message 1
  > commit message 2
```

### 9. 提交 Robbot 主仓库里的 submodule 指针

```bash
git status --short
git add vendor/deepseek-harness
git commit -m "chore: update deepseek-harness"
```

注意：真正需要提交的是 Robbot 主仓库里的 submodule 指针，不是把 DSH 源码复制进主仓库。

## 常用命令

### 查看当前 DSH 信息

```bash
pnpm dsh:info
```

输出包含：

- 当前 DSH commit
- 当前 DSH branch / detached HEAD
- Robbot 使用的协议 profile
- 当前 Node 版本
- DSH pnpm 版本

### 初始化 submodule

首次 clone 或 submodule 缺失时：

```bash
git submodule update --init --recursive
pnpm dsh:setup
```

### 重新构建 DSH

```bash
pnpm dsh:build
```

### 更新到官方最新

```bash
pnpm dsh:update
```

### 查看 DSH 内部 git 状态

```bash
git -C vendor/deepseek-harness status
```

### 查看 DSH 当前 commit

```bash
git -C vendor/deepseek-harness rev-parse HEAD
```

### 查看 DSH 官方远端

```bash
git -C vendor/deepseek-harness remote -v
```

### 查看 Robbot 主仓库记录的 submodule diff

```bash
git diff --submodule=log vendor/deepseek-harness
```

## 冲突和失败处理

### 情况 1：submodule 内部有未提交改动

脚本会拒绝更新，并提示：

```text
Refusing to update dirty DSH submodule.
```

处理方式：

```bash
git -C vendor/deepseek-harness status --short
```

然后三选一：

1. 如果这些改动要保留：在 DSH fork/分支里提交，或先 patch 备份。
2. 如果只是临时调试：stash。
3. 如果确定不要：丢弃这些改动。

不要在没看清楚 diff 的情况下直接清理。

### 情况 2：DSH 构建失败

先确认 Node 版本。

DSH 当前 engine 要求曾出现过：

```text
^22.19.0 || >=24.0.0
```

建议使用 Node 24.x，例如：

```bash
node --version
```

如果不是 22.19+ 或 24+，切换 Node 后再试。

### 情况 3：`pnpm test:dsh` 失败

这说明 Robbot adapter 和新 DSH 的 ACP 行为可能不兼容。

排查顺序：

```text
1. 看失败的是 createSession 还是 run/session/prompt
2. 看 ACP method 是否改名或 params 结构变化
3. 看 session/update 的 payload 是否变化
4. 更新 packages/dsh-adapter 的 mapper/transport
5. 再跑 pnpm test:dsh
```

相关代码：

```text
packages/dsh-adapter/src/transport/acp-transport.ts
packages/dsh-adapter/src/mapper/*
tests/dsh-contract/src/protocol/*
```

## 更新策略建议

建议不要在业务开发中随手更新 DSH。推荐固定节奏：

```text
1. 单独开一个 chore/update-dsh 分支
2. 执行 pnpm dsh:update
3. 看 DSH changelog / commit log
4. 跑 contract tests
5. 如果协议不兼容，先修 adapter
6. 单独提交 submodule 指针和必要适配代码
```

这样可以把“业务改动”和“上游 DSH 升级风险”隔离开。

## 最小验收标准

一次 DSH 同步只有满足下面条件才算完成：

```text
1. vendor/deepseek-harness 指向新的官方 commit
2. DSH install/build 通过
3. pnpm test:dsh 通过
4. Robbot 相关 build/test 通过
5. Electron 页面可以发送 prompt 并收到 assistant.delta
6. Robbot 主仓库提交了 submodule 指针变更
```
